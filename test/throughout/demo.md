# 超级智能管家 V2 全流程回归测试 Demo

---

## 一、测试概览

本次测试针对太保智能管家 V2 四阶段管道（L0 → L1 → L2 → L3）设计了 **5 个 batch、152 个样本点** 的全流程回归测试。测试目标：

| 测试维度 | 覆盖内容 |
|---------|---------|
| L0 标签感知 | manual / angry / urgent 标签的触发与混叠处理 |
| L2 风险评估 | 纯标签触发 + 32 个场景基础风险映射 |
| L1 意图路由 | 32 个场景 × 3 种变体（单轮经典 ×2 + 多轮 ×1） |
| 场景切换 | 对话历史中意图从 A 切换到 B 的路由准确性 |
| 混合风险 | 非截断型标签（sad / non_biz）与场景风险的叠加 |

## 二、V2 Pipeline 架构

测试覆盖的四阶段管道：

```
用户输入
    │
    ▼
┌─────────────────┐  ┌─────────────────┐
│ Stage 0: L0     │  │ Stage 1: L1     │  ← 并行发射
│ tag_judge_v2    │  │ purpose_route   │
│ → L0Output      │  │ → L1Output      │
└────────┬────────┘  └────────┬────────┘
         └────────┬───────────┘
                  ▼
         ┌───────────────┐
         │ Stage 2: Risk  │  ← 规则引擎（零 LLM，决策链可审计）
         │ assess_risk    │
         │ → RiskOutput   │
         └──────┬────────┘
                ▼
         ┌───────────────┐
         │ Stage 3:       │  ← 三级回复分派
         │ dispatch_by_   │
         │ risk()         │
         │ → DispatchResult
         └──────┬────────┘
                ▼
         EntranceResult (→ GUI)
```

### Stage 0: L0 跨场景标记

5 个判别性标签，Self-Consistency (k=5) 检测：

| 标签 | 动作 | 管道影响 |
|------|------|---------|
| manual | escalate | → case=0，立即转人工 |
| angry | risk_bump + skip_clarify | → case=0，安抚 + 优先转人工 |
| urgent | skip_risk | → case=2，跳过风险评估，直接操作指引 |
| sad | tone_soften | → 语气软化，不影响路由 |
| non_biz | redirect | → 礼貌引导回业务 |

### Stage 1: L1 意图路由

32 个二级业务场景分布：

| 一级意图 | 场景数 | 风险等级分布 |
|---------|--------|------------|
| 开场 | 3 | 全 low |
| 售前服务 | 11 | low × 1, medium × 8, high × 2 |
| 保单服务 | 7 | medium × 3, high × 4 |
| 理赔服务 | 4 | medium × 2, high × 2 |
| 增值服务 | 4 | low × 3, medium × 1 |
| 客户服务 | 4 | low × 1, medium × 2, high × 1 |

### Stage 2+3: 风险评估与分派

规则引擎链：`manual_override` → `urgent_skip` → `scene_base` → `angry_bump` → `compliance_scan`

三级回复模式：

| 风险等级 | 回复模式 | 说明 |
|---------|---------|------|
| low | generative | LLM 直出 |
| medium | faq_first | FAQ 优先 + LLM 兜底 + 审核 |
| high | faq_only_human | FAQ + 人工介入 |

## 三、5-Batch 测试设计

### Batch 1: 特殊标签感知与处理（10 条）

**目标**：验证 L0 标签检测 + entrance 层的标签拦截逻辑。

| 子集 | 样本数 | 测试内容 |
|------|--------|---------|
| 1.1 manual | 4 | 2 标准触发场景、1 计数测试（≥2 次转人工才触发）、1 混淆场景（含关键词但非转人工意图） |
| 1.2 angry | 2 | 1 单轮愤怒、1 多轮对话后触发的愤怒 |
| 1.3 urgent | 2 | 1 标准紧急、1 混淆场景（问道路救援是什么，非实际出险） |
| 1.4 mixed | 2 | 同时触发 manual + urgent 等多标签 |

**标签**：无预设标签（`-`），人工审阅控制信息 JSON。

### Batch 2: 风险判断系统测试（36 条）

**目标**：验证 L2 风险规则引擎对标签和场景的叠加判断。

| 子集 | 样本数 | 测试内容 |
|------|--------|---------|
| 2.1 纯标签 | 4 | manual → high, angry → high, sad → low, non_biz → low |
| 2.2 纯场景 | 32 | 每个场景 1 条经典样本，验证基础风险映射 |

**标签**：`{"risk_level": "low" | "medium" | "high"}`

### Batch 3: 单场景路由准确度测试（96 条）

**目标**：验证 L1 对 32 个场景的意图识别准确性。

每个场景 3 条：

| 类型 | 数量 | 设计 |
|------|------|------|
| 单轮经典 | ×2 | 直接表达意图的典型问法，两条互不相同 |
| 多轮 | ×1 | 2-4 轮对话，最近一轮仍指向同一场景 |

**标签**：`{"l1": "一级意图", "l2": "二级意图"}`

### Batch 4: 场景切换测试（5 条）

**目标**：验证对话历史中存在意图切换时，系统能否正确识别**最近的意图**。

| 切换方向 | 示例 |
|---------|------|
| 售前 → 保单 | 先说买保险 → 改为查保单 |
| 保单变更 → 理赔材料 | 先说变更受益人 → 改为问理赔材料 |
| 权益预约 → 道路救援 | 先约体检 → 改为要道路救援 |
| 售前 → 客服热线 | 先问保费 → 改为要客服电话 |
| 理赔进度 → 撤销报案 | 先查进度 → 改为撤销报案 |

**标签**：`{"l1": "...", "l2": "..."}`，标注的是**切换后的业务 B**。

### Batch 5: 混合风险判断（5 条）

**目标**：验证不会截断管道的标签（sad, non_biz）与业务场景的风险叠加。

| 子集 | 样本数 | 测试组合 |
|------|--------|---------|
| 5.1 单 tag + 单场景 | 3 | sad + 健康险投保（medium）、non_biz + 保单查询（medium）、sad + 产品咨询（low） |
| 5.2 多 tag + 单场景 | 2 | sad+non_biz + 续期缴费（medium）、sad+non_biz + 保单复效（high） |

**标签**：`{"risk_level": "low" | "medium" | "high"}`

## 四、测试工程架构

```
test/throughout/
├── agent prompt.txt                          # 用户原始测试需求
├── generate_5batch_samples.py                # 样本生成器（导入用）
├── test.py                                   # 测试执行器（CLI）
├── demo.md                                   # 本文档
├── 5batch_samples/
│   ├── 5batch_samples.xlsx                   # 152 条规范样本表
│   └── report/                               # 测试报告目录
│       ├── batch1_report_*.xlsx
│       ├── batch2_report_*.xlsx
│       ├── batch3_report_*.xlsx
│       ├── batch4_report_*.xlsx
│       └── batch5_report_*.xlsx
```

### 样本设计方法

样本采用 **LLM 生成 + 人工校验** 的方式制作：

1. 5 个专业 subagent 并行生成各自 batch 的样本草稿
2. 每个 subagent 收到精确的 prompt：场景定义、标签规范、样本数量、质量要求
3. 主 agent 汇总并校正：统一标签枚举值、修正场景映射错误、消除重复
4. 最终写入 `5batch_samples.xlsx`

这种方法确保样本自然、多样，避免传统程序化生成的机械重复。

### 测试执行

```bash
# 执行单个 batch
python test/throughout/test.py batch1    # 特殊标签感知
python test/throughout/test.py batch2    # 风险判断
python test/throughout/test.py batch3    # 单场景路由
python test/throughout/test.py batch4    # 场景切换
python test/throughout/test.py batch5    # 混合风险

# 执行全部
python test/throughout/test.py all
```

## 五、测试结果

### 5.1 总览

| Batch | 样本数 | 测试内容 | 准确率 | 关键指标 |
|-------|--------|---------|--------|---------|
| 1 | 10 | 特殊标签感知 | — | manual/angry 单轮漏检 |
| 2 | 36 | 风险判断 | **94.44%** | 34/36, 2 个错误 |
| 3 | 96 | 单场景路由 | **95.83%** | L1=100%, L2=95.83% |
| 4 | 5 | 场景切换 | **80.00%** | 1 个 L1+L2 错误 |
| 5 | 5 | 混合风险 | **100%** | 5/5 全对 |
| **JSON Parse** | **152** | **JSON 解析稳定性** | **100%** | **零失败，零重试** |

### 5.2 分项详情

**Batch 1 — 标签感知**：10 样本全部通过 JSON 解析。L0 标签检测对单轮 `manual`（1 次转人工不足以触发 ≥2 阈值）和单轮 `angry` 存在漏检；`urgent` 和混叠标签全部正确。

**Batch 2 — 风险判断**：34/36 正确（94.44%）。2 个错误：1 个 核赔 被误判为 理赔进度查询；1 个交通事故/理赔报案触发 urgent 但被赋予 medium（应跳过→null）。

**Batch 3 — 单场景路由**：96 样本，L1 一级意图 **100%** 准确，L2 二级意图 **95.83%** 准确。4 个 L2 错误：核保→产品咨询（1）、服务介绍→高频权益（1）、明确产品→产品咨询（2）。

**Batch 4 — 场景切换**：5 样本，1 个错误。理赔进度→撤销报案的场景切换中，L1 错误降至 售前服务。

**Batch 5 — 混合风险**：5 样本全部正确。非截断标签（sad/non_biz）与场景风险叠加结果符合设计。

### 5.3 核心发现

| 维度 | 状态 | 说明 |
|------|------|------|
| L1 一级意图 | ✅ 100% | 32 场景一级分类零错误 |
| L2 二级意图 | ✅ 95.8% | 4 个边界场景需 prompt 微调 |
| JSON 解析 | ✅ 100% | 控制字符转义修复完全消除 parse 失败 |
| 风险评估 | ✅ 94.4% | urgent 触发后风险空值判断需关注 |
| 并发性能 | ✅ | 16 线程 152 样本约 3 分钟完成 |

### 5.4 改进建议

1. **L0 标签**：manual 检测可降低单轮阈值，或改为累计计数 + 单次强烈表达也触发
2. **边界场景**：核保/核赔 vs 产品咨询/理赔进度 的区分需要在 prompt 中增加负例
3. **明确产品**：与产品咨询的边界模糊，建议合并或增加产品名关键词匹配
