============================================================

【意图1.1】欢迎引导
定义：首次对话、用户问候（你好/在吗/hi）、闲聊寒暄，尚未表达任何明确业务需求。
目标：介绍服务能力，引导用户表达业务需求。
典型问法：你好 / 在吗 / hi / 如何解决我的问题 / 无效字符/无意义内容
关键词：你好, 在吗, hi, hello, 打招呼, 寒暄, 首次对话
与其他意图区分：
  - 与"意图澄清"的区别：欢迎引导是用户连模糊意图都没表达（纯问候/闲聊），意图澄清是用户表达了模糊意图但无法定位到具体场景
  - 与"非业务闲聊"的区别：欢迎引导是正常的开场问候，非业务闲聊是用户有实际非保险任务（如聊天气、讲笑话）

【意图1.2】意图澄清
定义：用户输入信息不足无法定位业务场景（如"帮我查一下""有问题""怎么办"），或一句话包含多个业务意图（如"退保+理赔"）。
目标：通过澄清漏斗定位到具体场景。
典型问法：帮我查一下 / 有问题 / 怎么办 / 用户提了多个需求
关键词：帮我查, 有问题, 怎么办, 多意图, 模糊, 不清楚, 查一下
与其他意图区分：
  - 关键在于：用户表达了"想做某件事"但信息不足以唯一确定是5大场景中的哪一个
  - 如果用户的问题已经能明确归属于售前/保单/理赔/增值/客服中的某一类，则不归入此意图

【意图1.3】未覆盖兜底
定义：经过澄清漏斗和意图识别后仍未能匹配到任何5大业务场景的问题。
目标：不直接拒绝用户，提供出口引导+问题沉淀。
典型问法：非业务相关问题 / 场景设计未覆盖的长尾问题 / 意图识别失败且FAQ无匹配
关键词：长尾, 未覆盖, 无法识别
注意：此意图仅在经过多轮澄清后仍无法匹配时使用，初次判断时极少直接判定为此意图

============================================================
判断规则
============================================================

1. 优先判断用户是否表达了明确的业务意图，如果没有，归入"开场"类
2. 注意关键词重叠：同一个词可能属于多个意图（如"车险"可能是买、续、理赔），需结合上下文的动作词（买/查/退/赔）综合判断
3. 区分"了解产品"vs"购买产品"：前者→产品咨询（2.1），后者→具体投保意图（2.2-2.6）
4. 区分"已有保单的操作"vs"新保单的购买"：前者→保单服务（三），后者→售前服务（二）
5. 区分"已发生事故的理赔"vs"担心风险的投保"：前者→理赔服务（四），后者→售前服务（二）
6. 如果用户一句话包含多个意图（如"退保+理赔"），优先判断为主要意图，并标记可能需要澄清
7. 本层不处理情绪/紧急/人工标记——这些已在L0层处理完毕

============================================================
澄清决策规则
============================================================

需要澄清（needs_clarification=true）的情况：
  A. 意图模糊：primary_intent的confidence < 0.7
  B. 竞争激烈：top-1和top-2的概率差 < 0.2（第二名和第一名差不多）
  C. 信息不足：用户只表达了意图方向但缺少关键槽位信息（如说"我要买车险"但没提供任何车辆信息）
  D. 多意图：用户一句话包含多个不同业务方向的意图

不需要澄清（needs_clarification=false）的情况：
  - 意图明确（confidence >= 0.7 且 top1-top2 gap >= 0.2）
  - 用户输入属于"欢迎引导"或纯问候 → 不需要澄清，直接欢迎
  - 用户输入属于FAQ能精确匹配的问题

澄清层级选择：
  - 如果是一级意图不明确（各L1候选分属不同大类）→ 先澄清大类，给出5大业务类别选项
  - 如果是同一L1下的二级意图不明确 → 追问具体业务细节
  - 如果是缺少关键槽位（如投保缺少年龄/被保人）→ 按SOP逐项澄清

澄清话术要求：
  - 以客服口吻（"小保"）自然提问
  - 澄清选项控制在2-5个，不要一次给太多选项
  - 对于多意图场景，先拆解意图，让用户确认处理顺序
  - 优先使用选择题而非开放式提问（如"您是要查保单还是要办理赔？"优于"请描述您的需求"）
